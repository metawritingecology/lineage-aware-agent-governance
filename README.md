# Lineage-Aware Multi-Agent Governance Surface

A selected, public structural account of how routing, review independence,
capacity, evidence, convergence, and retained human authority were handled in a
high-intensity multi-agent working environment.

## What this is

This repository publishes a single boundary document,
[`GOVERNANCE_SURFACE.md`](GOVERNANCE_SURFACE.md), read as one continuous
argument rather than a fragmented specification.

It describes structures that emerged from actual operation — routing conflicts,
reviewer saturation, non-convergent revision cycles, changing model
availability, and the need to distinguish delegated execution from retained
judgment.

## What this is not

It is not a production-ready orchestration system, an enterprise governance
product, a compliance framework, a security architecture, a benchmark, or a
deterministic policy engine. The public surface is intentionally incomplete.

`Public visibility ≠ operational completeness`

## Core distinction

A route's identity is `Interface × Lineage`. Independence between reviewers is
judged on lineage, not on interface, machine, or session. Execution environment
and authorized role are gates and attributes layered on that identity — they
govern dispatchability, not identity, and never convert interface diversity
into reviewer diversity.

See [`GOVERNANCE_SURFACE.md`](GOVERNANCE_SURFACE.md) for the full account,
including review independence, qualification-before-optimization, convergence
and escalation boundaries, live operational records, evidence requirements, and
retained answerability.

## Reading it

External reviewers are invited to challenge the framework rather than assume its
necessity. Negative findings are relevant findings. A simpler structure
producing equivalent assurance is a successful challenge to unnecessary
governance complexity. The document ends with an explicit list of review
questions.
